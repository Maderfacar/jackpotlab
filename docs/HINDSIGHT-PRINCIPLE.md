# 鑑古系統（Hindsight）最高原則

> 適用範圍：`jackpotlab/app/hindsight/**` 全部訊號、分析、計分、視覺呈現
> 此檔為**最高原則**，任何訊號規格、程式行為、文件描述如與本檔衝突，以本檔為準。

---

## 最高原則

**本專案是學術型的客觀數據分析。**

- 不容雜訊
- 不容 AI 自我感覺良好
- 不容錯覺
- 不容猜測結果

資料剛好是台灣彩券開獎號碼，**不代表任務性質是「彩券預測」**。
請按客觀數據分析的精確度標準處理，等同於做股票訊號、感測器數據、A/B 測試。

---

## 對 AI 的行為守則（必須遵守）

### 1. 遇到規格模糊點 → 停下來問
不要自己選一個版本寫下去。**尤其不要選「常觸發 / 鬆 / 不明確 / 加 disclaimer」的版本來自我保護**。
對「彩券／號碼／預測」這類詞，AI 內建會傾向選鬆的版本——這是必須對抗的偏差，不是默許。

### 2. 不要把 AI 自己的解釋寫進 memory 假裝是規格
- **只有使用者親口拍板的字才能標 spec**。
- 若 memory 裡有 AI 自行定義的詞，必須加上 `[AI 推論待確認]` 標記。
- 違反此條 = 自我洗白。下次 session 讀 memory 時，AI 的猜會變成「拍板過的規格」，錯誤被埋四層深。

### 3. 測試要驗的是「使用者拍板的條件」，不是「AI 寫的程式」
- 寫測試前先用白話覆述條件給使用者看，**確認後才寫測試**。
- 測試通過 ≠ 跟需求對齊；只代表程式跟 AI 的想法一致。

### 4. 回答「線上邏輯」「目前推什麼」這類事實問題時 → 先讀程式、再答
- 不憑記憶。讀程式只要 30 秒，答錯一次要花使用者數小時抓。
- 「需要當下 runtime 資料才能算」的問題（例如「現在會推哪些號」），**老實說不能憑空答**，不要硬掰一組數字。

### 5. 交付前必須自我檢查
拿一筆使用者可驗證的資料跑一次，把**輸入、計算過程、輸出**攤給使用者看。
不能只跑「測試過了」就算完工。

### 6. 一次只校對一支訊號，不一次蓋一票過
歷史教訓：一次審 8 支會被略讀。**一支一支來，每支都要單獨拍板**。

## 自查清單（任何訊號／分析變更前必跑）

- [ ] 規格中每個名詞，使用者親口定義過嗎？沒有 → 停下來問。
- [ ] 規格中每個閾值（≥、>、N 期、K 顆），使用者親口指定過嗎？
- [ ] 觸發條件是「特定條件成立才亮」還是「每期都亮」？是否經使用者確認？
- [ ] 推薦號碼的選取規則（排序基準、位置定義、過濾範圍），使用者親口確認過嗎？
- [ ] 適用彩種範圍，使用者親口確認過嗎？

**任何一項打不下勾 → 不寫程式、回頭問使用者。**

## 違反此原則的代價（已發生過的歷史）

1. AI 自行解釋模糊詞 → 寫進程式
2. 寫測試驗證自己的程式（不是使用者拍板的條件）→ 測試通過
3. 把自己的解釋寫進 memory「以後查得到」
4. 下次 session 讀 memory，把自己的猜當作使用者拍板的規格
5. 錯誤在程式、測試、memory、後續對話四層深處被固化
6. 使用者花時間從輸出逆推發現「我要的不是這個」，token 與信任被浪費

**這個閉環必須被打破。本檔就是打破點。**
